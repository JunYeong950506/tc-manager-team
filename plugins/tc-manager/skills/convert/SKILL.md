# 기존 TC 정리

사용자 요청: $ARGUMENTS

`../../references/workflow.md`, `../../references/template.md`, `../../references/library.md`를 읽는다.

기존 결과의 약식 수행 준비·상태 조회·실행 피드백 반영이 목적이면 `../../references/readiness-workflow.md`의 후속 절차를 우선한다. 불필요한 전체 TC 재변환은 하지 않는다. 피드백에 TC 결함/요구사항 충돌이 있을 때만 해당 범위를 보완한다.

1. 실제 프로젝트·폴더 ID·TC 키와 대상 수를 확인한다. 한 건/여러 건은 입력에 따라 자동 처리한다. 사용자가 '아래 전체/하위 TC'를 지정하면 그 폴더의 후손까지 실제 ID로 수집하며 다시 포함 여부를 묻지 않는다. 하위 범위가 불명확할 때만 확인하고 형제 폴더·다른 프로젝트로 확대하지 않는다. 기존 원격 조회/파일 가져오기는 원문 수집이고 변환 완료가 아니다. 전체를 요청받았으면 내부적으로 나눠 끝까지 처리하며 묶음마다 계속할지 묻지 않는다.
2. 메타데이터와 전체 Test Script·출처를 원문 그대로 저장한다. XML/XLSX는 TC별로 분리하고 원본 파일·시트/행·TC 식별자와 단계 수를 대조한다. 필요한 파일 라이브러리가 없으면 지원 파일이나 연결된 조회 경로를 사용하고 읽은 척하지 않는다. 스크립트 유형·첨부·위임 단계·커스텀 필드는 잃지 않게 기록한다.
3. 기존 제목·목적·합격 기준을 유지하면서 양식을 정리한다. Precondition에 `[사전 조건]`·`[테스트 스텝]`·`[판정 기준]`의 사람용 전체 시나리오를 유지하고 동일한 시험을 Test Script로 구체화한다. 오래된 TC에 구획·조건·절차·판정 기준이 없으면 Jira와 Confluence에서 실제 탐색해 보완하고 출처를 남긴다. 미발견/충돌한 제품 기준은 추측하지 않고 최종 확인 대상으로 남긴다. 원문 조회본과 변환 초안을 다른 버전으로 저장한다. DB화만 요청했으면 원문 정규화·저장으로 끝내고 불필요한 AI 재작성은 하지 않는다.
4. Precondition 세 구획과 Script의 대응을 review.md에 기록하고 각 TC의 누락·의미 변경·임의 수치·중복과 `../../references/execution-readiness.md`의 단계 간 연결을 점검한다. 자체 점검으로 해결 가능한 입력·분기·관찰 방법을 보완하고, 기존 사용자 결정은 유지한다. 동일 TC의 여러 버전을 여러 TC로 집계하지 않는다. TC별 진행 상태를 workflow.json에 남겨 한 건 실패 때문에 완료 항목을 다시 작성하지 않는다. review.md에 변경 전후·근거·실행 준비 점검·반영 대상과 활성 미해결 사항을 모아 최종 검토를 받는다.
5. 기존 TC 갱신은 `../../references/publish-existing.md`, 별도 신규 TC를 만들라는 요청은 `../../references/publish-new.md`를 따른다. 단순 변환 요청을 복제 생성으로 바꾸지 않는다. 재조회한 확인본만 DB 기준 버전으로 선택한다.

결과: 전체 대상 수, 완료/검토 대기/차단 수, 원문과 초안의 위치, DB에 저장한 TC 수와 버전 수, 실제 Zephyr 변경 건수. 파일 준비와 원격 반영을 구분한다.

Zephyr HTML 원문은 `../../scripts/tc_source.py <원문JSON> --output <새평문JSON>`으로 별도 작업본을 만든다. 이 도구는 원문 JSON의 objective/precondition/description/testData/expectedResult만 평문으로 변환한다. 원문·첨부·위임 단계·커스텀 필드는 보존하며 평문 작업본은 시각적 첨부를 읽은 근거가 아니다. 이미 평문인 초안이나 HTML 문자열 자체를 시험하는 입력값에는 이 변환을 반복 적용하지 않는다.

대량 작업도 `examples/draft.json`의 내부 필드 `step/test_data/expected_result`를 사용한다. 원격 API 필드 `description/testData/expectedResult`를 초안에 그대로 복사하지 않는다. 첫 TC의 공용 형식·DB 저장을 확인한 뒤 나머지를 처리하고 초안 저장을 사람 승인까지 미루지 않는다. 사람 승인은 원격 반영과 구별한다. 제목이 같은 환경별 TC는 원문 전체를 대조한 뒤 자료 탐색을 재사용하되 환경·노드 역할·초기 상태의 차이는 별도로 점검한다.
