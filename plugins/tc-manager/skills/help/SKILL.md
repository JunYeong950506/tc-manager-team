사용자 요청: $ARGUMENTS

응답 첫 줄에 반드시 **현재 세션에서 호출된 TC Manager 도움말: v1.4.7**을 표시한다. 이 버전은 지금 전달받은 도움말 스킬에 포함된 값이다. 저장소·ZIP·설치 목록의 최신 버전으로 바꿔 표시하거나, 다른 세션과 이미 실행 중인 작업까지 같은 버전이라고 단정하지 않는다. 버전 질문에는 이 줄과 필요한 설명만 답한다. 도움말 요청에는 이어서 아래 사용법을 안내한다.

세 가지 업무만 안내한다. 설명 요청을 실제 처리로 실행하지 않는다.

| 업무 | 프로젝트 단축키 예시 | 플러그인 직접 명령 |
|---|---|---|
| 기존 TC 정리 | `/tc-manager 첨부 XML의 기존 TC를 정리하고 DB에 저장해줘.` | `/tc-manager:convert` |
| 신규 TC 작성 | `/tc-manager 이 Jira 변경 티켓에 필요한 TC를 작성해줘.` | `/tc-manager:create` |
| 테스트 준비 | `/tc-manager 이벤트 패널 회귀 테스트를 준비해줘.` | `/tc-manager:plan` |

프로젝트 단축키가 없는 팀원은 오른쪽 명령 뒤에 같은 요청을 쓴다. 단건·여러 건은 자동 구분하며 별도 batch/fill/revise 명령은 필요 없다. 수정은 `이 결과에서 ...를 수정해줘`, 재개는 `이 작업 폴더에서 이어서 해줘`로 요청한다.

신규 작성은 기본값(기능 검증)·성능·안정성을 체크박스로 여러 개 선택하고 직접 입력으로 원하는 상황을 추가할 수 있다. 이미 요청한 관점이나 같은 작업의 선택은 재사용한다. 직접 입력란은 Claude UI에서 Other로 표시될 수 있다.

이후 티켓당 1개로 제한하지 않고 근거 있는 시나리오 후보를 도출한다. 기존 TC와의 중복·재사용 여부를 함께 보여주고 사용자가 복수 선택한 후보를 상세 작성한다. 후보 선택 후 본문 최종 검토를 거쳐 Zephyr에 반영한다.

내용 검토와 약식 수행은 별도 상태로 보존한다. `이 TC의 약식 수행을 준비해줘`, `이 약식 수행 결과를 반영해줘`는 기존 업무의 후속 요청이다. 직접 명령을 쓰는 팀원은 `/tc-manager:convert` 뒤에 같은 요청을 쓴다. 약식 수행은 제한된 단계의 수행 가능성을 확인하며 정식 시험 Pass/Fail을 대신하지 않는다. 실행 Agent를 자동 기동하지 않고 전달 파일과 피드백 연결을 제공한다.

Jira·Confluence 탐색 → DB 대조 → 작성/선정·검토 → 사람의 최종 검토 → Zephyr 반영·재조회가 기본이다. 원문/조건/출처가 부족하면 스스로 탐색한 뒤 해결 못 한 제품 기준만 남긴다. 부모 점검과 독립 검토는 구분하며 Agent Team을 매번 실행하지 않는다.

테스트 준비는 기본 Test Cycle 제안이다. 영구 분류를 바꾸려는 요청은 폴더 이동으로 별도 구분한다. 실제 작성·이동 전 대상과 결과를 검토할 수 있게 보여준다.

DB 검색은 로컬 또는 조직이 설정한 저장소 범위이다. 설치만으로 Zephyr 전체 수집·팀 공용 DB·동기화가 완료되지는 않는다. MCP 연결이 없으면 초안·검토 자료를 보존하고 원격 반영을 완료라고 하지 않는다. API 토큰은 현재 MCP 환경 설정을 사용하며 OAuth로 되돌리지 않는다.
