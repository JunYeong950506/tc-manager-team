# 신규 TC의 시나리오 선택

새 create 작업은 본문 작성 전에 부모 Claude가 `AskUserQuestion`으로 작성 관점을 한 번 묻는다. 체크박스는 `multiSelect: true`로 요청한다. 관점 질문은 단건·여러 티켓 모두 작업 묶음당 한 번이며 TC마다 반복하지 않는다. 이후 `scenario-candidates.md`에 따라 구체적 후보를 도출하여 복수 선택받는다. 자연어 manage → create도 같은 절차다.

## 질문

현재 도구 스키마를 확인하고 다음 질문을 사용한다. `기본값`은 정상 동작·예외/경계 조건의 기본 기능 검증을 뜻한다. 첫 선택지에 배치하되 사용자가 제출하지 않은 선택을 응답으로 간주하지 않는다.

```json
{
  "questions": [
    {
      "header": "시나리오",
      "question": "어떤 시나리오로 TC를 작성할까요? 여러 개를 선택할 수 있고, 직접 입력으로 원하는 상황을 추가할 수 있습니다.",
      "multiSelect": true,
      "options": [
        {"label": "기본값", "description": "요구사항의 정상 동작과 관련 예외·경계 조건을 검증합니다."},
        {"label": "성능", "description": "응답 시간·처리량·자원 사용량 등 관련 성능을 검증합니다."},
        {"label": "안정성", "description": "반복·장시간 사용·오류 발생과 복구 상황에서 동작을 검증합니다."}
      ]
    }
  ]
}
```

직접 입력은 도구가 자동 제공하는 `Other`/직접 입력란을 사용한다. 중복되는 Other 선택지를 따로 추가하지 않는다. 직접 입력란의 표시 문구는 Claude UI에 따라 다를 수 있다. 선택지와 자유 입력을 함께 받으면 둘 다 보존한다. 직접 입력을 선택했지만 구체적인 내용이 전달되지 않았으면 해당 내용만 짧게 묻는다.

도구가 없거나 복수 선택 UI가 지원되지 않으면 `기본값 / 성능 / 안정성 / 직접 입력 — 여러 개를 골라 주세요. 예: 성능, 안정성 + 네트워크 복구`라고 짧게 묻는다. 텍스트 목록을 실제 체크박스라고 설명하지 않는다. 응답 전에는 독립적인 자료 조회만 진행하며 선택에 따른 TC 작성은 기다린다. 취소·빈 응답·시간 경과를 기본값 선택으로 처리하지 않는다. 사용자가 "기본으로 진행"이라고 답하면 기본값으로 확정한다.

## 선택의 적용과 재개

- workflow.json의 `scenario_preferences`에 `selected`(basic/performance/stability 배열), `custom`(직접 입력 원문), `source`(user_selection/user_request/plan_scope), `status`(pending/answered)를 저장한다. 직접 입력만 선택하면 selected는 빈 배열이어도 된다. 사용자 요청에서 이미 명확히 지정한 시나리오는 user_request로 기록해 그대로 적용하고 같은 질문을 반복하지 않는다.
- 재개·보완·여러 티켓 후속 작업은 같은 작업 범위의 answered 값을 재사용한다. 사용자가 다른 범위를 지정하면 새 값을 기록하고 변경된 TC만 재검토한다. plan 내부에서 공백을 메우는 create는 확정된 계획 범위를 plan_scope로 이어받는다. 부족한 TC마다 별도 선택 질문을 반복하거나 계획 범위를 넓히지 않는다.
- 기본값+성능, 성능+안정성, 세 항목 모두 등 복수 선택을 허용한다. 성능만 선택하면 기능 TC를 별도로 자동 추가하지 않는다. 필요한 준비·기본 동작 확인은 해당 시나리오 안에 포함한다.
- 선택한 관점을 Jira·Confluence 탐색, 기존 TC DB 대조, 작성·검토에 적용한다. 기존 TC로 충족되는 관점은 reuse/revise로 표시하고 신규 TC를 중복 생성하지 않는다. 서로 겹치는 검증은 하나의 TC로 통합하고 선택 관점과의 대응을 review.md에 남긴다.
- 직접 입력은 요구 범위를 구체화하는 요청이다. 제품 기대 동작과 합격 기준은 근거를 확인한다. 성능·안정성을 골랐다는 이유로 초 단위 기준·부하·반복 횟수·장시간 실행 시간을 임의 확정하지 않는다. 제안한 측정/실행 방법과 근거 있는 제품 기준을 구분하고 미확인 기준은 최종 검토에 남긴다.
- review.md에 선택 관점/직접 입력 → 신규·재사용 TC 또는 미충족 사유를 요약한다. 시나리오 선택은 작성 범위의 확인이며 최종 본문 승인이나 Zephyr 게시 승인이 아니다.
